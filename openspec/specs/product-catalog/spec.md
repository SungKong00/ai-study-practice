# product-catalog Specification

## Purpose

로컬 쇼핑몰 데모에서 상품의 이름과 가격을 등록하고 저장된 상품 목록을 확인한다. 클라이언트가 등록 결과를 다시 조회할 수 있고 잘못된 입력은 저장되지 않는 일관된 API 계약을 제공한다.

## Requirements

### Requirement: 상품 등록

시스템은 JSON `name`과 `price`를 받는 `POST /products`를 제공해야 한다(SHALL). 성공 시 고유한 양의 정수 `id`와 입력한 `name`, `price`를 JSON 객체로 반환하고 HTTP 201로 응답해야 한다(MUST). 가격 단위는 원이다.

#### Scenario: 유효한 상품 등록
- **WHEN** `{"name":"스터디 노트","price":12000}`을 전송한다.
- **THEN** HTTP 201과 고유 id, 같은 이름·가격을 포함한 상품을 반환한다.

#### Scenario: 무료 상품 등록
- **WHEN** 유효한 이름과 가격 0을 전송한다.
- **THEN** HTTP 201로 등록되고 반환 가격은 0이다.

### Requirement: 상품 입력 검증

이름은 공백만으로 이루어지지 않은 1~100자 문자열이고 가격은 0 이상의 정수여야 한다(MUST). 필수 값 누락, 잘못된 타입, 음수·소수 가격, 잘못된 JSON은 HTTP 400으로 거부하고 상품을 저장하지 않아야 한다(MUST).

#### Scenario: 유효하지 않은 입력 거부
- **WHEN** 이름 누락·공백·100자 초과, 가격 누락·음수·소수·문자열 중 하나를 전송한다.
- **THEN** HTTP 400으로 응답하고 상품 목록은 변경되지 않는다.

#### Scenario: 해석할 수 없는 JSON 거부
- **WHEN** JSON 구조가 올바르지 않은 본문을 전송한다.
- **THEN** HTTP 400으로 응답하고 상품은 저장되지 않는다.

### Requirement: 상품 목록 조회

시스템은 `GET /products`에 HTTP 200과 JSON 배열로 응답해야 한다(SHALL). 각 상품은 `id`, `name`, `price`를 포함하며 id 오름차순으로 정렬해야 한다(MUST).

#### Scenario: 빈 상품 목록
- **WHEN** 등록된 상품이 없는 상태에서 목록을 조회한다.
- **THEN** HTTP 200과 빈 배열 `[]`을 반환한다.

#### Scenario: 등록한 상품 조회
- **WHEN** 두 상품을 등록한 뒤 목록을 조회한다.
- **THEN** 등록 시 받은 id·이름·가격이 그대로 포함되며 id 오름차순으로 반환된다.

### Requirement: 로컬 데모 데이터 수명

상품은 실행 중인 애플리케이션에서 후속 요청으로 조회할 수 있어야 한다(SHALL). 애플리케이션 프로세스가 종료되면 데이터는 유지되지 않아야 한다(MUST).

#### Scenario: 재시작 후 빈 목록
- **WHEN** 상품을 등록한 프로세스를 종료한 뒤 앱을 다시 시작한다.
- **THEN** 상품 목록은 빈 배열이다.
