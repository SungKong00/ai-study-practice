## 1. PR 1 · 최신 제품 근거와 개발 인계

- [x] 1.1 `workflows/n8n/exports/evidence.json`에 읽기 전용 근거 조회와 커밋별 목차 캐시를 추가한다. 기존 볼륨에도 캐시 테이블과 미지원 응답용 분류 제약을 적용하고, 같은 SHA의 재사용·새 SHA의 갱신·상품 범위 밖 요청과 불완전한 목록 처리를 고정 입력으로 시험한다.
- [x] 1.2 Discord와 접수 폼의 고정 경로를 공통 조회로 교체한다. 근거가 있는 미지원 문의·원격 조회 실패·명세와 코드 충돌·검색과 정렬의 조합·공통 설정이 필요한 입력 검증을 두 진입점에서 검증하고 운영 가이드의 수동 fetch 설명을 바꾼다.
- [x] 1.3 세 역사 커밋을 고정한 재현 입력을 기존 평가 자료 옆에 둔다. 조회 도구는 로컬 Git 객체 또는 같은 형식의 fixture로 바꾸고 쓰기·실제 모델 호출을 차단한 CI 검사를 돌린다. 별도의 수동 모델 평가에서 같은 입력의 판정과 근거를 대조한다.
- [x] 1.4 README의 가격 상한·오류 미디어 타입과 현재 동작을 대조해 기존 계약을 보존한다. 중복 설명을 명세 링크로 바꾸고 하네스 가이드·이슈/리뷰 스킬의 탐색 지침을 맞춘다. 임시 복사본에서 검색만 옮겨 [분리 후 조회 예시](design.md#분리-후-조회-예시)에 대해 두 경로의 인용, 같은 답, 정렬 근거 누락 시 처리를 검증한다.
- [x] 1.5 로컬 Spring 리뷰와 PR 준비에 명세 검토를 연결한다. 기존 항목 수정과 독립 정책 분리 예시로 제안의 대상 경로, 규칙의 원본, 승인 예시와 테스트 연결을 한국어 리뷰·PR 양식에서 확인한다. 문서 경로 안내를 PR 스킬과 선택적 pre-push에서 재사용하고 기존 Gradle CI에 변경 경로별 문서 링크·OpenSpec 엄격 검사·무과금 회귀 검사를 연결한다.
- [x] 1.6 prepare-pr의 완료 분기를 연결한다. 중간 검사 생략, 회귀로 인한 제출 중단, 단일 PR 동기화·보관, 부분 PR의 미구현 delta 보존을 일회용 저장소에서 시험한다.

## 2. PR 2 · 수정·재승인·복구

- [x] 2.1 PostgreSQL 초기 스키마와 기존 볼륨용 마이그레이션을 작성한다. 두 번 실행해도 구형 대기·거절·게시 중·게시 완료 건의 제목·본문·이슈 번호가 보존되는지 확인한다.
- [x] 2.2 Discord에 공식 explore와 허용 근거 도구를 연결하고, 변경 요청부터 전용 discord-issue-refinement 스킬을 로딩한다. 명령어 없는 문의 → 일반 답글 → 모호한 변경 → 예시 합의 → 초안 수정 → 판본 승인 순서로 시험한다. 테스트에서 모델 입력의 공식·전용 지침, 새 사실 없는 턴의 근거 재사용, 승인 전 파일·이슈 생성 0건을 확인한다.
- [x] 2.3 Discord 수정 화면과 n8n 공통 검토 경로를 연결한다. 답변 후 같은 글의 변경 요청, 권한 없는 승인 거절, 긴 본문 전체 미리보기, 예시 수정으로 이미 지원하게 된 요청, 수정 후 옛 버튼 만료, 두 채널 동시 승인을 검증한다. DB 경합은 독립 연결로 시험한다.
- [x] 2.4 양쪽 승인 경로에 근거 재확인을 붙인다. 무관한 커밋은 기존 판본을 게시하고, 관련 정책 변경·이미 지원·조회 실패·구형 초안은 설계에 정한 상태로 끝나는지 시험한다.
- [x] 2.5 GitHub 생성 전후에 실패를 주입한다. 응답 유실 후 재클릭으로 추가 생성되지 않고 일치하는 기존 이슈만 연결되는지 확인한 뒤 복구·중지·되돌리기 절차를 n8n 운영 가이드에 반영한다.
- [x] 2.6 처리 기록, 비용 경고, 호출 상한, 기록 만료를 적용한다. 모의 사용량과 실패 응답으로 보류·회복을 검증하고 운영 기록에 전체 대화나 인증 정보가 남지 않는지 확인한다.
- [x] 2.7 테스트용 Discord와 허용된 GitHub 저장소에서 수정 전후 승인 버튼을 눌러 최종 이슈 수·실제 본문·스레드 링크를 대조한다. 실요청 3건을 비교할 항목과 측정 담당을 기존 평가 가이드에 연결한다.
