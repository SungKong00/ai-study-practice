# Spring Data JPA 구현과 검증

명세와 호출 코드에서 기대 동작을 찾고, 대상 모듈의 테스트 명령·프로필을 사용한다.

- **매핑** — 키 생성 방식·컬럼 타입·제약을 스키마와 대조한다. DB 제약 오류는 위반 값을 저장해 SQL 실행 또는 커밋 시점에 확인한다.
- **정렬·페이징** — 순서가 계약이면 SQL의 `ORDER BY`나 응답 전 정렬을 본다. 안정적인 페이징이 필요하면 제한 전 동률 처리 기준과 페이지 경계의 누락·중복을 검사한다.
- **연관 조회** — N+1이 의심되거나 자식 컬렉션을 포함해 부모를 페이징할 때 [연관 조회 검증](references/association-queries.md)을 따른다.
- **트랜잭션** — 함께 되돌릴 쓰기의 경계를 찾는다. 프록시 방식의 자기 호출은 호출 대상의 `@Transactional`을 우회한다. 쓰기 트랜잭션의 관리 엔티티는 `save()` 없이도 변경이 반영된다. `readOnly`는 최적화 힌트다.

**저장 결과 테스트**에서는 SQL 실행을 확인할 때 `flush()`, 1차 캐시를 비우고 재조회할 때 `clear()`를 쓴다. 2차 캐시까지 우회해 컬럼 값을 보려면 같은 트랜잭션에서 JDBC로 읽는다. **서비스의 커밋·롤백**은 테스트의 자동 롤백이 결과를 가리지 않도록 서비스 트랜잭션이 끝난 뒤 새 트랜잭션에서 행을 조회한다. 롤백은 첫 쓰기 뒤 실패시켜 검증한다. 실제 커밋에는 격리 DB나 데이터 정리를 사용한다. [Spring 테스트 가이드](https://docs.spring.io/spring-framework/reference/testing/testcontext-framework/tx.html)

Spring Boot에서 SQL이 필요한 테스트에만 `SPRING_JPA_SHOW_SQL=true`를 적용한다. 실행했다면 입력과 SQL·행 값을, 정적 검토라면 코드 위치와 예상 동작을 적는다. 결과가 ORM·DB 버전에 의존하면 그 버전을 밝힌다.
